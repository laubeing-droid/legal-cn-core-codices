## 一、命名规范问题

### 1.1 当前格式分布（已更新 · 旧格式已清零）

**目标格式**：`名称_日期_状态_ID.md`

| 格式类型 | 数量 | 占比 | 状态 |
|---------|------|------|------|
| 新标准格式（`名称_日期_状态_ID.md`） | 38,026 | ~88% | ✅ 已就绪，Front Matter 100% 完整一致 |
| __shortid 格式（`名称__8-12位hex.md`） | ~5,000 | ~11.5% | ❌ 无 YAML Front Matter——**当前最大数据债务** |
| IMA 格式 | ~16,300 | — | ⚠️ Front Matter 存在但字段名不统一（中英文混用） |

> **重要更正**：原诊断报告记载的 20,460 个旧格式（`状态_日期_名称_ID`）已于 2026-07-26~29 的多次治理中全部迁移为新标准格式。当前旧格式文件数为 0。

### 1.2 对 LLM 训练的实际影响

- **文件名格式对 LLM 训练几乎无影响**：LLM 读取的是 Markdown body + YAML Front Matter，不读取文件名
- **Front Matter 覆盖率才是真正的瓶颈**：38,026 正式法源文件 100% 完整，但 ~5,000 个 __shortid 格式文件完全缺失元数据
- **重命名优先级已降级**：从原 P0 "全部重命名"调整为 P2 "补充 __shortid 文件的 Front Matter"

### 1.3 名称含《》问题

- 约 7,455 个文件名含书名号——不影响 LLM 训练，仅影响人类浏览。建议作为低优先级批量替换。

### 1.4 日期待核/待补

- **已清零**：原 90 个日期待核文件已于 2026-07-29 全部处理完毕（见 memory.md）。
